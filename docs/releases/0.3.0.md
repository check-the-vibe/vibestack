# VibeStack 0.3.0

The CLI can discover and invoke registered workspace capabilities through
`capability list`, `capability schema`, and `capability call ID --input FILE`.
`mcp` supplies the thin authenticated stdio bridge. New capabilities use the
existing registry without a new bespoke client release.

Workspace profiles pin service identity. Private Codespaces access can use an
explicit protected gateway-token file, separate from the workspace credential;
no ambient GitHub token is loaded, redirects are rejected, and uncertain mutations
are not replayed. Shared source mounts work across project filesystem boundaries.

Start with `/AGENTS.md` on your private service. The release contains native
Linux/macOS amd64/arm64 clients, checksums, installer, compatibility manifest,
optional Linux host runners and GitHub Actions build provenance. Native installer
checks must pass before publication. curl 8.4+ is required by the installer.

Existing v1 workspace automation routes remain available. Old 0.2 control
commands that omitted authorization need upgrading or the authenticated `api`
command. New generic/MCP commands require 0.3.0. OAuth-only remote harnesses are
not supported; use a verified bearer client or the stdio bridge. External private
Codespaces gateways require their own authorized login, distinct from VibeStack.

Managed provider activation and the chat overlay are planned separately; this
release does not claim they are implemented. Release artifacts are never
silently replaced by this workflow. See the versioned CLI guide for provenance
verification, credential storage, error recovery and compatibility details.
