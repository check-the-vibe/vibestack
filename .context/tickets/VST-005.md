## Outcome and scope

Add the single workspace application process and nginx/static routing. Centralize authenticated dispatch for API and MCP adapters, use protected persistent credentials, and reserve the guide/discovery paths. Protect or retain private-only legacy routes; do not introduce anonymous pairing, a fleet registry or a new identity server. MCP client transport details belong to VST-011/VST-012.

- [x] SPEC-001 AC-04: static positive/negative publication checks passed through nginx.

## Development plan

1. Add one loopback Go process and supervised image packaging. Preserve the existing execution services and private desktop transport.
2. Add protected, instance-bound credentials with local issuance/revocation, compatibility with existing workspace tokens, and a shared principal resolver. Browser sessions require a human credential handoff and per-request revocation/CSRF checks.
3. Move legacy API aliases through authenticated adapters; block anonymous credential issuance and unknown API fallthrough. Keep the separate host runner outside this boundary.
4. Serve only the configured static publish root; reject hidden files, traversal, symlink escapes, unsafe methods and directory listings. Reserve guide/discovery and future MCP/capability routes.
5. Test authentication, file permissions, cross-instance/Origin failures, revocation, body/output limits and actual nginx routing. Adapt existing acceptance clients to authenticate rather than weakening the boundary.
6. Build and accept a disposable image before any Codespace replacement. Record the ticket-owned foundation checks; live MCP and guide/client acceptance remain in dependent tickets.

## Verification scope

Published-file boundaries through nginx; invalid/missing credentials before dispatch; internal listeners; compatibility-route bypass attempts; restart with existing protected credentials. Record API/MCP end-to-end parts pending until their adapter tickets complete.
