# Pass 1: write a feature specification

Use with: feature description or initiative queue entry; intended outcome;
known constraints. Fill in missing context from the repository before asking.

> Read root AGENTS.md, .context/workflow.md, the initiative and relevant source
> and architecture documents. Describe the existing behavior from evidence.
> Write one focused specification from .context/templates/specification.md.
> Define user journeys, scope, interfaces, authority boundaries, errors,
> migration and measurable acceptance criteria. Compare the consequential
> design options and make a recommendation with reasons. Distinguish decisions
> from assumptions; ask only for decisions that block useful progress. Preserve
> prior user authorization and record its source. Do not implement the feature
> during this pass. Do not describe proposed endpoints or tools as available.
> Finish with a reviewable specification, unresolved decisions, and the next
> planning action. Mark it ready only when necessary decisions are resolved.

Expected output: linked specification and updated initiative reference, on a
branch with a planning ticket and manifest. A specification-writing ticket may
start against a draft specification; its scope is documentation, not feature
implementation.
