# Pass 2: build the project plan

Use with: specification path and its acceptance criteria.

> Read the specification, .context/workflow.md and the actual implementation.
> Resolve or identify decisions that prevent execution. Break the feature into
> the smallest useful reviewable increments, including contracts, migration,
> failure behavior, verification and documentation. Create tickets from the
> ticket template with dependencies and explicit acceptance evidence. Map every
> specification criterion to at least one ticket. Identify integration order,
> potential parallel work, and any work that cannot begin yet. Prefer one
> ticket per branch and define the expected base; do not create execution
> branches merely to reserve names. Update the specification's linked plan.
> Keep execution status in tickets. Report scope gaps and the first actionable
> ticket. Do not start feature implementation during this planning pass.

Expected output: a complete linked ticket plan, dependency order, criterion
coverage, and an actionable first development pass. No ungrounded deadlines or
invented approvals.
